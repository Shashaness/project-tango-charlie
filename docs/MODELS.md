# Milestone 14 model pipeline

Preferred format: **glTF 2.0 in self-contained GLB**. No dependencies were added.
The strict standard-library JSON/GLB reader decodes a small tested subset, rather
than accepting unsupported features through a larger scene engine. Format math
follows the [Khronos glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).

## Supported subset

One embedded BIN buffer; selected/default scene; named nodes and hierarchy;
TRS or column-major node matrix; normalized `[x,y,z,w]` quaternion rotation;
indexed/non-indexed TRIANGLES; FLOAT VEC3 POSITION and optional NORMAL;
FLOAT or unsigned normalized VEC2 TEXCOORD_0; unsigned byte/short/int indices.
Accessor/view offsets, stride, bounds and alignment are validated. Missing
POSITION, cycles/multiple parents and bad references fail with useful errors.

Opaque `baseColorFactor` supplies existing unlit RGB rendering. RGBA,
metallic/roughness and double-sided metadata are preserved. Normals/UVs are
retained in immutable CPU primitive arrays; the existing shader does not consume
them. No lighting/shader overhaul or texture upload occurs. Existing rendering
has no back-face culling, so both faces remain visible.

Explicitly unsupported: external buffers/data URIs, JSON `.gltf` files, textures,
alpha MASK/BLEND, emissive materials, skins/joints, animation playback, morphs,
sparse accessors, extensions/compression, cameras/lights, additional attributes
and non-triangle primitive modes. These fail before GPU upload rather than being
silently misinterpreted. Metallic/roughness rendering is intentionally unlit.

## Transform spaces and API

NumPy matrices use mathematical column-vector multiplication, matching the
existing engine. Shader upload transposes storage, not transform mathematics.

```
node_local = imported_base * runtime_delta
node_world = parent_world * node_local
root_world = vehicle_or_world * root_conversion * root_local
clip = projection * view * node_world * vertex
```

`ModelNode.base_matrix` is imported/rest data; the public property returns a copy.
TRS-authored nodes also retain immutable `base_trs` components for future pose
interpolation; matrix-authored nodes retain the exact matrix without inventing a
decomposition.
`set_delta(translation=..., rotation=..., scale=...)` supplies rest-relative local
TRS. `set_pose(...)` supplies an absolute local TRS override instead. Neither
changes imported data. `model.reset_pose()` clears all overrides/deltas without
reloading the asset. World matrices are recomputed through the small hierarchy.

`model.find_node("LeftLeg")` returns exactly one named node, raises KeyError with
available names if absent, and raises ValueError on ambiguous duplicate names.
`print_hierarchy()` prints names/primitive references. `bounds()` returns AABB in
converted model/vehicle-local meters; `bounds(world)` returns the transformed
AABB. Runtime articulation affects bounds. Gameplay collision is unchanged.

A single proper 180-degree Y rotation `diag(-1,1,-1,1)` converts an asset authored
facing +Z to Project Tango Charlie's -Z forward. It flips X and Z together, preserving
right-handedness and +Y up. There are no per-node/per-vertex sign inversions.
glTF does not impose an aircraft nose direction; +Z-facing is this pipeline's
asset authoring convention. `convert_coordinates=False` is an explicit opt-out
for already engine-oriented assets. `scale=` is optional uniform root scaling;
otherwise one model unit is one meter, with no automatic normalization.

## Ownership and integration

`load_glb()` builds CPU-only Model/ModelNode/MeshPrimitive/Material data. Model
operations never allocate GL resources or write physical vehicle state.
`ModelResources` uploads each unique primitive once using the existing Mesh
class; all referencing nodes share that upload. It renders base color via the
existing position/color shader. Repeated draws only update matrices/draw calls.

Mesh owns VAO/VBO/EBO. ModelResources owns its Mesh objects and closes each once;
Renderer owns ModelResources and closes it while its GLFW context remains current.
Construction failure closes completed uploads; Mesh handles its own partial
allocation failure. CPU loading may precede context creation; GPU upload/draw/
delete occur only in the existing renderer's context/main-thread lifecycle.
Normal primitive Fighter/VTOL/Battledroid resources and rendering remain default.
No existing gameplay control, physics, camera or collision was changed.

`engine/asset_paths.py` resolves packaged assets/shaders from the project location,
independent of shell working directory. User-specified paths are ordinary paths
relative to their shell directory or absolute paths. Load errors include the path.

## Original technical asset and proof

`assets/models/test/hierarchy_test.glb` is generated by:

```sh
python scripts/generate_hierarchy_test.py
```

No Blender or downloads are needed. Two colored box primitives are reused by
eight mesh instances. Vertex data deliberately interleaves POSITION/NORMAL/UV
with view/accessor offsets and 32-byte stride; indices are uint16.

```
Root
  Body
  Nose
  LeftWing
  RightWing
  LeftLeg
    LeftLegShape
    LeftFoot
  RightLeg
    RightLegShape
    RightFoot
```

Run `python main.py --enemies 0 --model-test`. The primitive craft stays visible;
the test model is attached 7 m right/12 m forward in vehicle space. It follows
vehicle movement/rotation while retaining independent child transforms. The
16-second automatic proof repeats: 0–4 s LeftLeg 0→30 degrees (foot follows),
4–8 s LeftFoot 0→30 degrees additionally (parent unaffected), 8–12 s articulated
model root moves/rotates, 12–16 s reset to imported pose. This is a temporary
technical exercise, not a transformation/walking animation system or new input map.

`python main.py --model-test --model-path /absolute/example.glb --enemies 0`
displays a supported custom GLB at rest without assuming aircraft node names.
`python main.py --inspect-model /absolute/example.glb` prints hierarchy/bounds
without creating a window. Repeated launch/ESC cycles exercise upload/cleanup.
Use an absolute path to main.py when launching from another working directory.

## Future Blender export convention

Export glTF 2.0 GLB, +Y up (the exporter handles Blender's native up axis), one
unit per meter. Author the nose to become +Z in exported glTF, and verify in the
technical viewer. Use sensible applied geometry scales, opaque base colors,
triangulated meshes and exported normals. Avoid textures/skins/animations/
extensions until those features are supported.

Keep movable parts as separate, meaningfully named parented nodes. Do not join
all wings/legs/feet into a single giant mesh; child foot nodes need to remain
addressable below leg pivots. Pivot nodes with geometry children avoid unwanted
inherited shape scale. No prototype aircraft, transformation poses, animation
system, articulated combat or M15 model is included in M14.
